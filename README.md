# Экспорт и импорт переписки Claude Code

Два скрипта на Python для работы с историей сессий Claude Code:

- **`export_claude_code.py`** выгружает переписку всех проектов в Markdown (для чтения), JSON (для обработки) и raw (точная копия для переноса).
- **`import_claude_code.py`** загружает экспорт обратно в Claude Code, после чего сессии снова открываются через `claude --resume`.

Подходит для резервной копии, переноса истории на другой компьютер, поиска по старым разговорам и их архивации в читаемом виде.

## Требования

- Python 3.9 или новее
- Сторонние пакеты не нужны, используется только стандартная библиотека
- [uv](https://docs.astral.sh/uv/) — по желанию, для установки команд и разработки

## Установка

Скрипты можно запускать напрямую (`python3 export_claude_code.py`), а можно поставить как команды:

```bash
uv tool install .
```

После этого доступны `claude-code-export` и `claude-code-import` с теми же опциями. Без установки их можно вызвать из папки проекта через `uv run claude-code-export ...`.

## Разработка

Проект оформлен через uv, линтер и форматтер — [ruff](https://docs.astral.sh/ruff/), проверка типов — [ty](https://docs.astral.sh/ty/). Настройки лежат в `pyproject.toml`.

```bash
uv sync                    # окружение и dev-зависимости
uv run ruff check          # линтер
uv run ruff format         # форматирование
uv run ty check            # проверка типов
```

## Где Claude Code хранит переписку

```
~/.claude/projects/
├── -home-user-myapp/                 ← папка проекта (путь, где все символы кроме букв и цифр заменены на «-»)
│   ├── <session-id>.jsonl            ← одна сессия = один файл, одна строка = одна запись
│   └── <session-id>/subagents/
│       └── agent-<id>.jsonl          ← переписка субагентов
└── -home-user-other-project/
    └── ...
```

Оба скрипта по умолчанию работают с этой папкой. Другое место задаётся через `--source` для экспорта и `--target` для импорта.

## Экспорт

```bash
python3 export_claude_code.py [опции]
```

### Примеры

```bash
# Всё в Markdown → ./claude_code_export
python3 export_claude_code.py

# Markdown для чтения + raw для последующего импорта
python3 export_claude_code.py --format md raw --sidechain -o ~/claude-backup

# Только один проект и только за последний месяц
python3 export_claude_code.py --project myapp --since 2026-10-01

# Подробный экспорт: вызовы инструментов, их результаты, размышления
python3 export_claude_code.py --tools --thinking --max-tool-output 0

# Плюс всё одним файлом
python3 export_claude_code.py --single-file
```

### Опции

| Опция | Описание |
|---|---|
| `-s, --source PATH` | Папка с проектами (по умолчанию `~/.claude/projects`) |
| `-o, --output PATH` | Куда сохранить (по умолчанию `./claude_code_export`) |
| `--format md json raw` | Один или несколько форматов (по умолчанию `md`) |
| `--project TEXT` | Только проекты, путь которых содержит подстроку. Можно указать несколько раз |
| `--since YYYY-MM-DD` | Только сессии, начатые не раньше этой даты |
| `--until YYYY-MM-DD` | Только сессии, начатые раньше этой даты |
| `--tools` | Включить вызовы инструментов и их результаты |
| `--thinking` | Включить блоки размышлений |
| `--sidechain` | Включить переписку субагентов |
| `--raw` | Не вырезать служебные сообщения (вывод слэш-команд, пометки о прерывании) |
| `--max-tool-output N` | Предел длины результата инструмента в Markdown, в символах (по умолчанию 4000, `0` — без предела) |
| `--single-file` | Дополнительно собрать всё в `all_conversations.md` |

### Форматы

| Формат | Что это | Для чего |
|---|---|---|
| `md` | Читаемый Markdown с заголовками, временем и сворачиваемыми блоками | Читать, искать, хранить в архиве |
| `json` | Упрощённая структура: метаданные сессии и список сообщений | Анализ, обработка своими скриптами |
| `raw` | Байт-в-байт копия исходного `.jsonl` | Перенос без потерь и импорт |

### Результат

```
claude_code_export/
├── INDEX.md                          ← оглавление со ссылками по проектам
├── index.json                        ← то же в машиночитаемом виде
├── all_conversations.md              ← только с --single-file
└── home-user-myapp/
    ├── 2026-11-01_Fix_login_bug_3f2a1b4c.md
    ├── 2026-11-01_Fix_login_bug_3f2a1b4c.jsonl
    └── 2026-11-01_3f2a1b4c__agent-1.md      ← субагент (с --sidechain)
```

Файлы называются `дата_название_id`. В шапке каждого Markdown-файла указаны путь к проекту, id сессии, время начала и конца и ветка git.

Что скрипт делает с содержимым:
- Убирает `<system-reminder>` и служебные сообщения (если не указан `--raw`).
- Claude Code записывает ответ ассистента по частям, поэтому части склеиваются в одно сообщение.
- Повторяющиеся записи пропускаются.
- Испорченные строки JSON пропускаются с предупреждением, экспорт продолжается.

## Импорт

```bash
python3 import_claude_code.py <папка-экспорта или файл> [опции]
```

### Примеры

```bash
# Сначала посмотреть, что будет сделано
python3 import_claude_code.py ~/claude-backup --dry-run

# Импортировать
python3 import_claude_code.py ~/claude-backup

# Перенос с macOS на Linux: проекты лежат по другому пути
python3 import_claude_code.py ~/claude-backup --remap /Users/me=/home/me

# Несколько замен путей
python3 import_claude_code.py ~/claude-backup --remap /Users/me/work=/srv/work --remap /Users/me=/home/me

# Импортировать копии рядом с существующими сессиями
python3 import_claude_code.py ~/claude-backup --new-ids

# Один файл
python3 import_claude_code.py ~/claude-backup/home-user-myapp/2026-11-01_Fix_login_bug_3f2a1b4c.jsonl
```

### Опции

| Опция | Описание |
|---|---|
| `-t, --target PATH` | Куда импортировать (по умолчанию `~/.claude/projects`) |
| `--remap OLD=NEW` | Заменить начало пути проекта. Можно указать несколько раз, применяется первое совпадение |
| `--project TEXT` | Только проекты, путь которых содержит подстроку |
| `--new-ids` | Выдать сессиям новые id, чтобы не конфликтовать с уже существующими |
| `--overwrite` | Перезаписывать существующие сессии (по умолчанию они пропускаются) |
| `--dry-run` | Ничего не записывать, только показать план |

### Как работает импорт

1. Рекурсивно ищет в папке файлы `.jsonl` (формат raw) и `.json` (формат json). Если для сессии есть оба, берёт `.jsonl`.
2. Определяет путь проекта по полю `cwd` внутри сессии, применяет `--remap` и вычисляет имя папки так же, как Claude Code.
3. Переписку субагентов кладёт на прежнее место, в `<session>/subagents/`.
4. Если ничего менять не нужно, raw-файл копируется без изменений. С `--remap` или `--new-ids` он пересобирается.
5. Существующие сессии не трогает без `--overwrite`.

После импорта откройте папку проекта и запустите:

```bash
claude --resume
```

### Raw или JSON

**Для переноса используйте `raw`.** Импорт из `json` возможен, но часть данных теряется:

| | raw | json |
|---|---|---|
| Текст сообщений | ✅ | ✅ |
| Вызовы инструментов и результаты | ✅ | ✅ (результат становится текстом) |
| Размышления | ✅ | ❌ отбрасываются: без подписи API не даст продолжить такую сессию |
| Изображения | ✅ | ❌ вместо них текстовая пометка |
| Статистика токенов, служебные поля | ✅ | ❌ |
| Исходные id сообщений и цепочка ответов | ✅ | ❌ строится заново |

Markdown-экспорт обратно не импортируется, он только для чтения.

## Перенос на другой компьютер

```bash
# Старый компьютер
python3 export_claude_code.py --format md raw --sidechain -o ~/claude-backup
# скопировать ~/claude-backup на новый компьютер

# Новый компьютер
python3 import_claude_code.py ~/claude-backup --remap /старый/путь=/новый/путь --dry-run
python3 import_claude_code.py ~/claude-backup --remap /старый/путь=/новый/путь
```

`--remap` нужен, только если проекты на новой машине лежат по другому пути: Claude Code находит сессии по пути к папке проекта.

## Замечания

- Формат файлов Claude Code не документирован официально и может меняться между версиями. Скрипты читают его без жёстких требований: незнакомые типы записей пропускаются.
- В экспорте может оказаться всё, что попало в разговоры, в том числе содержимое файлов, токены и пароли из вывода команд. Храните и передавайте экспорт с осторожностью.
- Перед импортом с `--overwrite` полезно сделать резервную копию `~/.claude/projects`.
- Формат `raw` копирует только `.jsonl` сессий и субагентов. Служебные файлы рядом с субагентами (`agent-*.meta.json`, `agent-*.prefix.json`) не переносятся.
